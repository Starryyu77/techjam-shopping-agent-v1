# 已知经验

- 当前运行环境不允许测试往系统临时目录写文件，因此最小商品目录改成只读 fixture；业务逻辑没有依赖临时文件。
- 规则基线会把 `sterling silver` 同时误识别成材质和颜色，且对中英混合的拒绝、停止句覆盖不足。这正是方案 B 需要解决的通用 bad case，不应继续堆单句规则。
- 开发集 state exact 为 0.422，说明单轮意图看似不错仍会在五轮中累积错误；提示词比较必须同时看连续状态。
- 早期阶段本地模型尚未安装，因此当时只有规则弱基线；后续 Qwen 结果均以模型实际启动后的报告为准，不能预先声称提升。
- 官方目录中存在不可解析的价格占位值；数值在唯一入库入口统一清洗为 `null`，不能让单条脏商品终止整个会话。
- Qwen3-8B Q4_K_M 单独运行时 Domain 较好但 slot/state 较差；未经提示词训练前不能因为“用了大模型”就替换安全基线。
- Hybrid 在验证集把 composite 从规则的 0.812 提到 0.851，并保持 no-mutation 1.000；V1 默认采用规则高置信度快路、Qwen 低置信度补位。
- 英文属性不能用裸子串匹配：`ring` 会误中 `exploring`，`red` 会误中 `preferred`；解析、过滤、重排和追问必须共用完整词边界。
- 原始商品短语对检索很有价值，但不能伪装成已归一化 slot；把两者分开后，dev/validation 语义指标不退步，官方 Hit Rate@10 从 0.550 提升到 0.950。
- 召回索引和重排文本必须覆盖同一组商品字段；此前 `details` 进入 FTS5 却没进入重排，是公开集低分的直接原因之一。
- 品类归一化不能覆盖原始层级：`Boots Mid-Calf → boots` 适合语义状态，但完整细品类必须作为检索证据继续参与召回和重排；修正后公开 Hit Rate@10 从 0.950 提升到 0.970，且没有丢失原有命中。
- 早期 `exp_selfevolve/` 会把保留集信号带入改写和选优，容易形成数据泄漏；它现在只作为历史实验保留，正式循环统一走 `prompt_lab.py`，仅用 dev 驱动改写、validation 做验收。
- 提示词文件末尾换行曾让同一版本产生不同模型结果；加载时统一 `.strip()`，保证保存格式差异不会改变实际送入模型的 system prompt。
- target 与 judge 同模型同端点只能算 self-judge，不能当作独立语义裁判；每轮必须显式记录该关系，并让确定性 Gold 指标保持最终否决权。
- 固定口令本身不等于冻结；held-out 门禁必须绑定提示词和评测代码的系统哈希，并在读取标签前写入一次性清单，避免换版本或换 judge 重跑选优。
