# V1 自检循环

每次只改一个可说明的原因：意图提示词、规则、状态更新、召回或追问策略之一。

```text
跑开发集 → 按共同原因分组 bad case → 修改一处
    ↓
5 个单元测试通过
    ↓
跑开发集和验证集
    ↓
验证变好且安全指标不退步？──否→撤销本轮提示词升级并记录原因
    │
    是
    ↓
更新当前版本；最终冻结后才看一次保留测试集
```

完成条件：

1. Python 编译与单元测试通过。
2. 本地千问启用时，`http://127.0.0.1:8080/health` 返回 `status=ok`。
3. 开发、验证报告可复现。
4. `json_compliance` 和 `no_mutation_preservation` 不下降超过 0.01。
5. 验证集 `composite` 提高才升级提示词。
6. 连续两轮没有验证提升时停止自动改提示词，回到 bad case 人工分析。

失败诊断顺序：先看 JSON 契约，再看 domain，再看 dialogue act，再看 slot，最后看连续状态。不要用总体分掩盖某个安全指标的退化。
